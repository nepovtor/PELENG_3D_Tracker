Ниже сохранён первоначальный отчёт о проверках в изолированной среде; его ограничения больше не описывают все последующие испытания на устройствах.

Дата: 29 октября 2026. Среда разработки: Linux контейнер, Python 3.13, NumPy 2.3.5, OpenCV 4.13.0, pytest 9.0.2. **Нет MacBook, Xcode и физического iPhone** — аппаратные проверки выполнить здесь невозможно.

## Отсутствующие проверки — блокеры полного эксплуатационного статуса

- Не запускался `xcodebuild` (Xcode недоступен в Linux), приложение не было подписано Apple ID и не устанавливалось на физический iPhone.
- Mac Camera через AVFoundation в этом окружении не проверена (нет macOS и встроенной Mac-камеры).
- Не было реального обмена кадрами Mac–iPhone по домашней Wi-Fi, реальной стереокалибровки, измерений точности на физическом объекте, длительного теста нагрева и потерь соединения.
- HTTP транспорт с токеном **без TLS** не предназначен для недоверенных сетей; нужна отдельная проверка приватности и модель угроз перед продакшеном.

## Пользовательская проверка на устройствах

1. Mac: `python -m pytest -q`, затем `python -m peleng3d serve` и настоящее превью mac camera.
2. Xcode: выбрать физический iPhone, включить automatic signing, `Product > Build`, затем `Run`.
3. iPhone: pairing в той же Wi-Fi сети, разрешить камеры и local network; смотреть **оба живых кадра одновременно**.
4. Проверить число matched/dropped и uncertainty; если большие — исправить сеть прежде калибровки.
5. Распечатать 9×6 внутренние углы с измерением клетки, сохранить 20–30 реальных синхронных пар, запустить калибровку и проверить RMS/baseline.
6. Медленно двигать реальный цветной объект; увидеть изменения X/Y/Z, проверить физическое положение точек по рулетке, сохранить CSV, переоткрыть CSV.
7. Отключить Wi-Fi/iPhone, убедиться в честной потере сигнала и отсутствии новых ложных 3D-точек, затем восстановить подключение.
8. Сравнить измерения с эталонными расстояниями и записать среднюю ошибку и P95 в дополнительном протоколе испытаний.
