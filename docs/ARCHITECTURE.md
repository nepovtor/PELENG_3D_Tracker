# Архитектура фактической реализации

## Два настоящих источника

**Mac:** `MacCamera` открывает OpenCV AVFoundation camera (на macOS), читает настоящий `cv2.VideoCapture.read`, фиксирует monotonic timestamp **после получения кадра**, центрирует/crop и ресайзит в 640×480 без растяжения, хранит кольцевой буфер на 90 кадров. Работа в отдельном потоке, чтобы HTTP/UI не блокировали получение.

**iPhone:** SwiftUI + `AVCaptureSession`/`AVCaptureVideoDataOutput` (реальная задняя камера), нормализует изображение до 640×480 JPEG через CoreImage, связывает каждые ~100 мс данные с монотонной меткой `ProcessInfo.systemUptime` и отправляет на Mac. Максимум один запрос на передачу в полёте: ограниченная очередь и естественный backpressure. Если сеть нестабильна, кадры пропускаются вместо бесконечного накопления задержки.

**Приёмник и ядро:** FastAPI, `Engine.receive()` сверяет секрет/устройство/формат/номер, декодирует JPEG через OpenCV, сопоставляет кадры, ищет зелёную метку в обоих изображениях, триангулирует лишь при подходящей калибровке. Результаты хранятся в CSV, не отправляются в облако. `server.py` подключает только реальные потоки. Синтетические изображения существуют **только** в `tests/`.

**Интерфейс Mac:** полнофункциональная локальная web desktop-панель (интерфейс запускается в Safari/Chrome на Mac), не изображение-макет. Реальные `GET /api/dashboard`, JPEG-превью и кнопки для принятия пар калибровки, расчёта, настройки HSV, записи и экспорта. Секретный PIN отображается только на localhost.

## Время и синхронизация

iPhone делает серию запросов `GET /api/time` и получает `t_server_receive`, `t_server_send` (Python `time.monotonic`). Используя собственные t0 и t3 (ProcessInfo uptime), оценивает offset = ((t1-t0)+(t2-t3))/2, uncertainty=RTT/2, выбирает лучший из четырёх образцов, повторяет периодически. Захваченная метка iPhone + offset приводится к домену времени Mac. Среди локальных кадров выбирается ближайший **ещё не использованный**. Пара отвергается, если Δt + uncertainty > 90 мс или uncertainty >45 мс. Относительное смещение и точность программной выборки не гарантируют hardware-синхронизацию shutter; это особенно важно при быстром движении. Время захвата на Python отмечается после read, а на iOS — при получении callback; это вносит latency bias, требующий исследования на реальных устройствах.

## Геометрия и отображение

`geometry.py` — внутренние параметры из chessboard 9×6, размер клетки в **метрах**, `cv2.calibrateCamera` для каждой, `cv2.stereoCalibrate` с фиксированными внутренними параметрами для пары; сохраняются `K1,D1,K2,D2,R,T`. `cv2.undistortPoints`, `cv2.triangulatePoints` и контроль `cv2.projectPoints`; отклоняются невидимые/отрицательные глубины, RMS калибровки >3px, ошибка репроекции >3.5px, точки дальше 10m. Система координат **первой Mac-камеры**, +X вправо, +Y вниз, +Z вдоль оптической оси, метры. Dashboard рисует изометрическую проекцию **реально измеренных** последних 180 точек, а не полноценный движок WebGL.

## Хранение

`~/Documents/PELENG3D/calibration_pairs/` — изображения только после явного «Сохранить пару». `stereo_calibration.json` — профиль матриц, разрешения, Mac camera index, device UUID и iPhone camera mode. `sessions/*.csv` — только настоящие принятые 3D-координаты и метрики качества. Секрет сопряжения только в оперативной памяти.

## Безопасность

Сервер слушает LAN для узких iOS endpoint: `/api/health`, `/api/pair`, `/api/time`, `/api/frame`. Локальная панель, превью, выгрузки и управляющие эндпоинты проверяют localhost. PIN шестизначный, рандомный, до 8 ошибочных попыток в минуту, после pairing 32-байтный случайный URL-safe session token, сервер допускает одного активного iPhone. Клиентские запросы не используют cloud. **HTTP не зашифрован**; PIN и bearer token потенциально наблюдаемы на скомпрометированном LAN. Требуется TLS и сертификатный pinning для эксплуатации вне доверенной сети, rate limiting не является полноценной защитой от DDoS. Сервер не предназначен для открытого интернета.

## Расширение

`MacCamera` и `Engine.receive` уже являются двумя source adapters под общий формат `TimedFrame`. Настоящее внедрение USB/IP/промышленных камер требует нового adapter и тестов, но **не переписывания** `geometry.py`, `detection.py`, `sync.py` или `store.py`. Обратная совместимость протокола должна сохраняться по `protocol: 1` или меняться явно, с одновременным обновлением iOS/Mac.
