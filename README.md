# PELENG 3D Tracker — MacBook + iPhone

**Реальные кадры двух камер → программная синхронизация → стереокалибровка → трёхмерные координаты зелёного маркера → запись CSV.** Проект создан с нуля, не использует синтетические видеопотоки в рабочем режиме. Первое устройство — MacBook со встроенной камерой, второе — iPhone с нативным iOS-приложением на AVFoundation.

> **Статус проверки:** автоматические Python-тесты и синтаксис Swift проверены в среде разработки. Сборка в Xcode и тесты на физических MacBook/iPhone здесь **не проводились**: на них требуются устройства пользователя. Наличие исходников ещё не является подтверждением успешной установки или заявленной реальной точности. См. `docs/TEST_REPORT.md`.

## Состав

- `peleng3d/` — Python/FastAPI, Mac OpenCV capture, pairing, timestamp matching, HSV, stereo calibration, триангуляция, запись.
- `web/` — локальная инженерная панель управления для Mac: живые кадры, сетевой адрес и PIN, калибровка, траектория, диагностика, история и CSV.
- `ios/PELENGCamera/PELENGCamera.xcodeproj` — **настоящий Xcode-проект** SwiftUI для физического iPhone; задняя камера, предпросмотр, JPEG-поток, сопряжение, оценка сдвига часов.
- `tests/` — unit и HTTP integration tests; искусственные изображения **только в тестах**, не в runtime.
- `docs/` — архитектура, протокол, калибровка, безопасная установка без штатива, отчёт о проверках, правила Codex.
- `AGENTS.md` — постоянные правила Codex: уточнять существенные решения, экономить токены, исправлять адресно, проверять сквозной результат.

## 1. Mac — установка и старт

Требуется **macOS 13+**, Python 3.10+ (рекомендуется 3.11–3.13), камера, локальная Wi-Fi сеть. Для iOS-сборки понадобится **Xcode 15+** (рекомендуется актуальный Xcode, совместимый с вашей macOS).

1. Распакуй `PELENG_3D_Tracker.zip` в `~/Downloads` (в Finder дважды кликни ZIP).
2. В Terminal:

```bash
cd ~/Downloads/PELENG_3D_Tracker
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --timeout 180 --retries 12 -r requirements.txt
python -m pytest -q
python -m peleng3d serve
```

3. Открой **http://127.0.0.1:8765** на Mac. Разреши Terminal/Python доступ к камере в macOS **Системные настройки → Конфиденциальность и безопасность → Камера**. Если понадобится, закрой FaceTime, Zoom и другие программы, занявшие камеру.
4. Вверху/в боковой панели найдёшь реальный IP Mac и **шестизначный PIN**, обновляемый при каждом новом запуске сервера. Сервер доступен другим устройствам сети по TCP `8765`; веб-панель и записи доступны только с localhost Mac.
5. Если встроенная камера имеет не нулевой индекс, останови сервер (`Control+C`) и выполни `python -m peleng3d serve --camera 1`. Индексы зависят от Mac.

### Две или более USB/UVC-камеры

Параметр `--camera` можно повторять. Первые две камеры становятся активной
стереопарой; дополнительные источники отображаются в диагностике и готовы для
последующего выбора пары:

```bash
python -m peleng3d serve --camera 1 --camera 2
python -m peleng3d serve --camera 1 --camera 2 --camera 3
```

После замены камеры обязательно собери новую калибровку. Обычные UVC-камеры
сопоставляются программно по монотонным часам Mac: это не аппаратный триггер,
поэтому интерфейс честно показывает ошибку пары и может отклонять кадры.

В многокамерном режиме iPhone работает монитором и пультом. Во вкладке
«Обзор» введи адрес Mac и PIN: приложение покажет камеры, XYZ и записи, а также
позволит начать или завершить запись. Чтобы вернуть iPhone в роль второй
камеры, запусти сервер только с одним параметром `--camera`.

**Быстрый повторный старт:** `scripts/start_mac.command` (возможен запрос разрешений macOS). Скрипт создаст venv при необходимости и установит зависимости; при нестабильном интернете первый ручной запуск удобнее. Если `pip` долго загружает OpenCV — это сетевое ограничение, попробуй другую сеть.

### Автоматический фоновый запуск

Чтобы сервер запускался при входе в macOS и автоматически восстанавливался после сбоя, один раз выполни:

```bash
./scripts/install_autostart.sh
```

Для постоянного запуска с двумя камерами переустанови службу так:

```bash
PELENG_CAMERA_INDEXES=1,2 ./scripts/install_autostart.sh
```

После этого панель постоянно доступна на **http://127.0.0.1:8765**, пока пользователь вошёл в macOS. Команды управления:

```bash
./scripts/autostart_status.sh
./scripts/uninstall_autostart.sh
```

Логи находятся в `~/Library/Logs/PELENG3D/`. Сервис использует камеру `0`, порт `8765` и данные `~/Documents/PELENG3D`. Если macOS запросит доступ к камере для Python — разреши его. PIN изменяется только после фактического перезапуска процесса.

## 2. iPhone — приложение и запуск

Нужен **iPhone с iOS 16+**, доступной задней широкоугольной камерой, Xcode на Mac и Apple ID для **бесплатной персональной подписи**.

1. На Mac открой `ios/PELENGCamera/PELENGCamera.xcodeproj` в Xcode.
2. Выбери слева target `PELENGCamera` → **Signing & Capabilities** → **Automatically manage signing** → свою **Team** (Personal Team/Apple ID). Если Bundle ID уже занят, замени его на уникальный, например `com.твояфамилия.pelengcamera` латиницей.
3. Подключи iPhone по USB, разблокируй и подтверди «Доверять этому компьютеру». Включи **Developer Mode**, если iOS попросит (Настройки → Конфиденциальность и безопасность → Режим разработчика); после перезагрузки подтверждай запрос.
4. Выбери физический iPhone как Run Destination, нажми **▶ Run**. При первой установке iPhone может попросить доверять сертификату разработчика.
5. На iPhone разреши доступ к **Камере** и **Локальной сети**. Поставь телефон горизонтально в стабильной ориентации.
6. Убедись, что iPhone и MacBook в одной Wi-Fi сети и маршрутизатор не блокирует обмен между клиентами. В приложение впиши **IP Mac** (например `192.168.1.23`, **не** `127.0.0.1`) и PIN из веб-панели Mac. Нажми «Подключить и начать».
7. На Mac должны показываться **две настоящие обновляющиеся картинки**, а также FPS, счётчик синхронных кадров и ошибка синхронизации.

iPhone не обязан использовать **Continuity Camera**: поток идёт **из отдельного собственного приложения**. Облако и интернет для работы не нужны. Приложение нельзя просто установить из ZIP без сборки и подписи в Xcode.

## 3. Установи устройства без штатива

MacBook устойчиво поставь на стол, крышку направь камерой к рабочей зоне. iPhone положи/закрепи **на устойчивой нескользящей подставке** (например, заводская подставка или книжная опора с бортиком), камерой в ту же зону. Начальный базис — примерно **25–40 см**, расстояние до объекта — около **1–2 м**. Не клади телефон на край стола или на экран ноутбука. Важны отсутствие вибрации, хорошее освещение, неподвижность камер после калибровки. Подробно и со схемами: `docs/SETUP_WITHOUT_TRIPOD.md`.

## 4. Калибруй обе камеры

1. На Mac в веб-панели нажми **«Открыть доску для печати»**, распечатай `web/checkerboard.svg` **A4 landscape, 100%, без масштабирования**. Это **10 × 7 клеток**, **9 × 6 внутренних углов**, номинально **25 мм** на клетку.
2. **Проверь линейкой** напечатанную сторону клетки. Введи фактическое значение в поле «Размер клетки в метрах» (25 мм = `0.025`).
3. Держи доску неподвижно в поле зрения **обеих** камер; нажми **«Сохранить пару»**. Доска должна быть видна целиком. Для каждой следующей пары меняй угол, расстояние и положение доски в кадрах.
4. Сделай минимум **12**, желательно **20–30** разных пар; не снимай 12 раз одно и то же положение. Затем нажми **«Рассчитать калибровку»**. Увидишь RMS и базис камер; ошибочная геометрия отклоняется.
5. **Не двигай Mac/iPhone после калибровки.** При изменении положения камер, выбранной камеры, ориентации, кропа, фокуса/зума повтори калибровку. Сохранённый профиль привязан к устройству, размеру и режиму потока, но физическое перемещение устройства автоматически не обнаруживается.

Подробно: `docs/CALIBRATION.md`.

## 5. Реальное измерение и экспорт

Покажи **круглый ярко-зелёный предмет** одновременно обеим камерам. Интерфейс поставит маркеры на цветном объекте, а после успешной триангуляции покажет **X, Y, Z в метрах** в координатах Mac-камеры (`+X` вправо, `+Y` вниз, `+Z` вперёд) и график последних измерений. Если света/цвета недостаточно — измени HSV-пороги в боковой панели.

Нажми **«Начать запись»** и перемещай маркер **медленно**. После **«Завершить и сохранить CSV»** запись появится в «Сеансах» и на диске в `~/Documents/PELENG3D/sessions/*.csv`. CSV содержит координаты в метрах, ошибку репроекции, ошибку сопоставления кадров и погрешность оценки часов. **При отсутствии достоверной позиции точки в CSV не добавляются.**

### Диагностика

- **Mac camera offline:** выдай разрешение Terminal/твоему Python, закрой другие приложения с камерой, попробуй `--camera 1`.
- **iPhone не соединяется:** проверь Wi-Fi, IP Mac из панели, актуальный PIN, firewall/macOS входящие TCP 8765, отключи VPN/изоляцию Wi-Fi клиентов. На iPhone разреши локальную сеть.
- **Есть картинка, нет синхронных пар:** проверь значение «Ошибка часов ±», задержку, сеть; не делай быстрых движений, попробуй стабильную точку доступа. При оценке неопределённости более 45 мс система не выдаёт измерение.
- **Доска не распознаётся:** убедись, что все 54 внутренних угла различимы **обеими** камерами; убери блики, обеспечь фокус и равномерный свет.
- **Точки нет:** сначала выполни калибровку и настрой цвет. Центр зелёного круга должен обнаруживаться в обеих камерах; при плохой геометрии и слишком большой ошибке репроекции измерение отбрасывается.
- **IP недоступен:** приложение iPhone принимает только приватные IPv4-адреса и `.local`-имена; сервер печатает LAN адрес в Terminal.

## Ограничения честно

- Синхронизация программная по Wi-Fi. Это **не аппаратный триггер** и не подтверждает миллиметровую точность для быстро движущихся объектов. Ошибка времени определяется из обмена запросами; измеренная реальная точность требует контрольных физических испытаний.
- Транспорт **HTTP с авторизацией по одноразовому PIN + токену на доверенной локальной сети, без TLS**. Это стартовая инженерная реализация: нельзя использовать её в публичном Wi-Fi. Для промышленного развертывания добавить TLS с проверкой сертификата, надёжное обнаружение и протоколы безопасности.
- Реализованы повторяемые локальные OpenCV/AVFoundation-источники для USB/UVC и прежний режим Mac + задняя широкоугольная камера iPhone. В текущей версии реконструктор использует одну выбранную пару — первые два индекса запуска; одновременное N-view-слияние, IP/RTSP и промышленные SDK **не реализованы**.
- Реальный Xcode build и физический end-to-end должны быть выполнены на твоих устройствах. Смотри `docs/TEST_REPORT.md`.

## Работа Codex

Перед новой задачей Codex должен следовать `AGENTS.md` и только относящейся к ней части `docs/PROJECT_SPEC.md`. Рефакторинг крупного участка и изменение сетевого контракта согласовываются заранее. Поддельные кадры, метрики, демо-траектории в runtime запрещены.
